## 1. Directive interpretation and governing contracts

The governing system is Cloudflare's design system in its two published layers, applied by surface:

**Source-to-site token contract (pin, from review pass 1).** The site's token names follow Kumo's actual namespace; every site token maps to a Kumo source name or a brand constant. Kumo color roles (verified live): `--color-kumo-canvas`, `--color-kumo-base`, `--color-kumo-elevated`, `--color-kumo-recessed`, `--color-kumo-control`, `--color-kumo-brand`, `--color-kumo-brand-hover`, `--color-kumo-line`, `--color-kumo-hairline`, `--color-kumo-focus`, plus `kumo-contrast`, `kumo-overlay`, `kumo-interact`, `kumo-fill-hover`. Text roles are a separate namespace: `--text-color-kumo-default`, `--text-color-kumo-link`, `--text-color-kumo-brand`. TRAP, do not blur it: the COLOR role `kumo-brand` is the blue action color; the TEXT role `kumo-brand` is orange. Unused Kumo roles are listed as available-not-used, never silently invented. Exact values come from the Kumo theme-generator config and colors page at implementation time, cited per token.

**Product layer = Kumo** for interface and product-like surfaces: semantic surfaces, blue action, dark neutrals (canvas oklch(10% 0 0), elevated 12%, recessed 15%, base 17%), status set only for real states, 8px control radius (verified: Kumo Button is h-9 + rounded-lg; the wider .125-.75rem ladder is a LOCAL mapping derived from component utilities, not a Kumo token set, and is labeled as such), hairline-vs-line separation (never border plus drop shadow on one card), concentric nested radii, no LayerCard stacking, dialogs stay mounted, focus rings per component source (Button 2px `kumo-brand` ring; Input 1.5px `kumo-focus` ring), 14px floor for interface content, sentence-case headings, semibold headings and medium inline emphasis, NO tracking overrides in product text, hover color IMMEDIATE (the design-skill rule is normative; the one `transition-colors` class in Button source is not copied), Phosphor icons (`@phosphor-icons/react`).

**Brand layer = the Cloudflare brand guide** for brand and story surfaces (hero, manifesto, connect, and the home's brand moments): Tangerine `#F6821F`, Ruby `#FF6633`, Mango `#FBAD41`; secondary colors (Lemon, Blueberry, Raspberry, Blackberry, Cherry) only for diagrams/illustration if ever needed; orange present in every brand layout (small accent to full-bleed - the design work ranges within that); white space as the complement in light mode; black for type; the brand typographic roles implemented WITH their tracking values on brand surfaces only: uppercase semibold eyebrow at +5 percent, body at -2 percent, headline at -3 percent, subheadline at -3 percent, URL at -3 percent, each with its role leading. The boundary is explicit: brand tracking applies to brand/story surfaces; product/interface text follows Kumo's no-tracking rule. Cloudflare's logo and flare are NOT used.

**Mode contract (pin):** adopt Kumo's `data-mode=\"light\" | \"dark\"` mechanism with semantic tokens; Tailwind `dark:` variants are banned in components (per Kumo's own guide). System preference decides, the existing toggle overrides; the time scheduler retires. System-first resolution is a SITE policy, not a Kumo requirement. Brand/story surfaces in dark mode sit on Kumo dark surfaces with orange accents retained (the white-space rule is a light-mode brand rule); verify contrast and screenshots in both modes.

**Links (pin, from Kumo Link docs):** underlined blue inline links; plain treatment for navigation and footer; inherited-color links only in semantic contexts; external-link indicator plus `rel=\"noopener noreferrer\"` on new-tab links; focus state in the same acceptance checklist.

**Lint contract:** no raw hex in components or ad hoc anywhere; the ONLY permitted hex literals are the official brand constants in the canonical token file. No `backdrop-filter`. A stale-utility checker gate (see T6b) replaces the false comfort of the token checker for class renames.

**Identity marks exception (explicit):** the owner's double-slash mark and wordmark are an IDENTITY asset, kept and recolored to the new palette, explicitly outside the Cloudflare system (the standing identity rule protects owner symbols; Cloudflare's own marks are never substituted). Veto-able at preview.

**Superseded and retired:** glass classes, SignalField, StructureGrid, refraction filter/hooks, cipher remnants, Lexend, Geist Mono, old signal/ink ramps, field-accent teal, time-scheduled theme, solid-by-default rule, negative-tracking heading law, mono-accent restraint. ADRs 0002, 0003, 0005 get \"Superseded by ADR-0007\" headers. ADR-0001 (tier precedence) survives re-mapped; ADR-0004 survives re-checked; ADR-0006 survives.

**Unchanged:** all site copy (hero role line and motto are owner-settled), site structure, deploy flow, no-dash rule, no-secrets rule.

**Unverified/dashboard rule:** build only against public Kumo + brand sources; a needed behavior with no public evidence becomes a labeled local Kumo-compatible decision, never claimed dashboard fidelity.

Color, typography, geometry, density, material, motion, components, states, icons per section 1's contracts. Additional pins:

3. Owner gate: dev preview review with per-item veto notes; main only on his explicit word; production readback after his merge closes T2's release check.
4. Rollback: revert the task's merge commit (reverse order if dependents exist), push, poll preview, record. Nothing touches main pre-approval.
5. Secrets gate before every push: inspect diff for identity-copy changes, secrets, untracked files, main/moon-watch accidents.
